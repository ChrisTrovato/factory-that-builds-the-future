# Working on The Factory

Start with a small observable change. Preserve stable lesson/project IDs so saved progress and cross-links remain valid. Keep model equations, units, assumptions, and tests synchronized. Keep the experience self-paced; do not add misleading industrial claims or academic-credit promises.

Run `npm run check`, inspect the changed flow in a browser, update `docs/work-log.md`, and explain the result in the commit or pull request. Public issues and changes must not contain private notes, credentials, personal course records, or copied private chat context.

The live application has no install step or runtime dependencies. Avoid adding a service, tracking SDK, or account requirement without explaining the user benefit and privacy impact.
